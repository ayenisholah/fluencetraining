# LendLoop: rules for coding agents

This file is the contract for any AI agent (Claude Code, Codex, Copilot, Cursor and others) working in this repo. Humans follow the same rules in [docs/CONTRIBUTING.md](docs/CONTRIBUTING.md). If this file and the code disagree, **the code wins**: stop and report the mismatch instead of guessing.

## 1. How to work

- **Do exactly what was asked.** No unrequested refactors, renames, reformatting, dependency changes, new features or "while I'm here" fixes. If you notice something else, mention it in your reply.
- **Ask when the request is ambiguous** or a decision belongs to the maintainer: data model changes, new dependencies, deleting data, anything that costs money, anything touching secrets or production.
- **Never invent APIs, files, scripts or env vars.** Before using one, find it (`grep -rn`, read the file). Before writing a helper, search for an existing one. Section 4 lists the ones you must reuse.
- **Read before you edit.** Match the surrounding style, naming and comment density. Copy the pattern of the nearest similar code (a sibling component, the neighbouring Convex function, the existing test file).
- **Prove it works.** Run the checks in section 6 for what you touched and report the real output. Never claim a test passes that you didn't run. If something fails or you skipped a step, say so.
- **Keep changes small and reviewable.** One logical change per commit.
- **Cite code as `path:line`** when explaining.

## 4. Rules that are easy to break

**Convex (server)**
- Every public query or mutation starts with a guard from `convex/lib/auth.ts`: `requireUser`, `requireAdmin`, `requireToolOwner`, `requireLoanParty` (or `getCurrentUser` where signed-out callers are allowed). Throw with `badRequest`, `forbidden` or `notFound`.
- Identity comes from `ctx.auth` through those guards. **Never** accept `userId`, `ownerId`, `role` or `status` from the client.
- Every new public function must be added to `PUBLIC_FUNCTIONS` in `convex/access.test.ts` with its guard. That test fails otherwise. Internal-only functions use `internalQuery` / `internalMutation`.
- Write loan status with `setLoanStatus` (`convex/lib/loanRecord.ts`), and tool name, description or status with `setToolStatus` / `toolSearchFields` (`convex/lib/toolRecord.ts`). Don't patch those fields directly.
- Anything that should notify someone goes through `enqueueLoanEvent` (`convex/lib/outbox.ts`) in the same mutation. Never call n8n directly.
- Validation shared with forms lives in `convex/lib/rules.ts`, which must not import Convex server code (the browser bundle uses it).
- Other users only ever see a **first name** (`firstName` in `convex/lib/people.ts`). Never return another user's email or full name, and never put them in notification payloads. The one exception is admin screens behind `requireAdmin` (`convex/admin.ts`), which show full names and emails.
- Lists are paginated on the server with `pageArgs` + `numberedPage` (`convex/lib/pagination.ts`; page sizes 10, 25, 50 or 100) and searched with `vSearch` / `searchTerm` (`convex/lib/search.ts`). Writes that users can repeat are rate limited with `assertWithinRateLimit`.
- New derived or indexed fields are optional, maintained by the `*Record.ts` helper, and backfilled in `convex/migrations.ts`.

**UI (client)**
- Colours come from tokens in `app/globals.css`. **No hex values** in components.
- Destructive actions confirm with `useConfirm()` (`components/ui/ConfirmDialog`). `window.confirm` and `alert` are lint errors.
- Filters, search and view live in the URL via `useUrlState` (`lib/useUrlState.ts`), rendered under `<Suspense>`. Page number and page size are local state (`lib/useNumberedPage.ts`).
- Form errors appear only after a submit attempt, then update live.
- Every new screen or component gets an axe test (`test/axe.ts`), keyboard support and visible focus. New `components/ui` parts also get a story.
- Client code must not import `convex/_generated/server`, `convex/lib/auth` or `convex/lib/outbox` (lint error). Call the server through `api.*` from `convex/_generated/api`.

**n8n**
- Don't hand-edit `n8n/workflows/*.json`. Change the workflow in n8n, run `npm run n8n:export` (it refuses to export secrets), review the diff, then run `npm run test:n8n`.
- Webhooks both ways are HMAC-signed (`convex/lib/hmac.ts`). Never weaken or skip verification.

## 5. Never

- Edit generated files: `convex/_generated/**`, `next-env.d.ts`, build output (`.next/`, `storybook-static/`, `infra/cdk.out/`).
- Change `package-lock.json` with any npm other than 10 (the one bundled with Node 22, which CI uses). Newer npm writes lockfiles that CI's `npm ci` rejects. On a newer Node, run `npx npm@10 install ...`.
- Commit secrets, `.env*` files, real email addresses or keys. This repo is **public**. Configuration values go in GitHub variables or AWS Secrets Manager (`scripts/aws/put-external-secrets.sh`).
- Disable or loosen a lint rule, type check, test or CI step to make your change pass. Fix the code. An `eslint-disable` needs a `-- reason` and must be the narrowest possible.
- Use `--no-verify`, force-push to `main`, or merge without CI passing.
- Add AI attribution to commits or PRs: no `Co-Authored-By:` AI trailers and no "Generated with ..." lines.
- Run anything that changes AWS or production (`cdk deploy`, `scripts/aws/*` that write, SSM commands) unless the maintainer asked for it in this task.

## 6. Checks to run

| You changed | Run |
|---|---|
| Anything | `npm run format:check && npm run lint && npm run typecheck && npm test` |
| UI or styles | also `npm run check:contrast` and `npm run test:storybook` |
| A user flow | also `npm run test:e2e:public`; signed-in flows need the local stack (`npm run setup`, see README › Testing) |
| `n8n/` | `npm run test:n8n` |
| `infra/` | `cd infra && npm run typecheck && npm run lint && npx cdk synth --strict -q`, then `npx cdk diff` and check nothing stateful (the EC2 instance, volumes, secrets, backup vault) is replaced |

Run a single test file with `npx vitest run path/to/file.test.ts`. The pre-commit hook (husky + lint-staged) formats and lints staged files. Fix what it reports; don't bypass it.

## 7. Infrastructure and cost

- Production runs on an AWS **free-plan** account (credits only). Don't add always-on paid resources (RDS, ElastiCache, NAT gateways, load balancers, extra EC2 instances, more Synthetics canaries) without the maintainer's approval.
- Renaming or moving a CDK construct changes its logical ID and **replaces** the resource. Never do that to the instance, volumes, secrets or the backup vault.
- Pushing to `main` deploys automatically (`.github/workflows/deploy.yml`). See [docs/operations/ci-cd.md](docs/operations/ci-cd.md).

## 8. Commits, PRs and docs

- Branch from `main` as `feature/...` or `fix/...`. Subject: imperative, sentence case, 72 characters or fewer, no prefix ("Refuse to approve expired requests"). Body: why.
- Open a PR using `.github/pull_request_template.md`. PRs are squash-merged after CI passes.
- Update the docs your change affects: `docs/product/user-stories.md`, `docs/architecture/api.md` (Convex functions), `docs/architecture/data-model.md` (schema), `docs/CHANGELOG.md` (under `## Unreleased`), and a new ADR in `docs/architecture/adr/` (next free number, Context / Decision / Consequences) for any new decision.
